# 蒸发修复说明

日期：2026-11-20（当日锁定，当日禁止改口）
题目：实体键桥 · 撤映后孤儿无痕蒸发
库：SQLite `data/app.db`（本地夹具）
登录：沿用 `admin / 123456`

## 缺陷症状（已复现）

撤映后实体行从正式区消失，但**没有**进入冲突区，映射册/互证卡仍按“在册”报账。
结果是：正式区没有、冲突区没有、账上还有——孤儿蒸发，账面无法追溯。
只改孤儿角标（改 `reconcile_cards` 显示或只改 `mapping_register.state`）**不修复**缺陷，且判失败。

## 择定口径：甲路径（唯一）

**甲：撤映同一事务内先迁入冲突区、再删除正式区；迁入或删除任一失败，两者一起回滚。**

甲乙互斥，本仓只走甲，不混用乙：

- 乙（正式保留 + 打 `orphan` 标记）**不采用**。
- 因此撤映成功后正式区必须为空、冲突区必须有该实体的待处置记录，二者同事务生效。
- 禁止只改孤儿角标；写入前发现实现偏离甲路径，拒绝发布并记“蒸发偏了”。

## 五处同态

撤映成功的唯一合法落点是下面五处同时成立：

| # | 位置 | 表 / 接口 | 撤映成功后 |
|---|------|-----------|-----------|
| 1 | 正式区 | `formal_entities` / `GET /api/formal` | 该 (old_key, entity_key) 行消失 |
| 2 | 冲突区 | `conflicts` / `GET /api/conflicts` | 新增 `reason='撤映'`, `status='待处置'` |
| 3 | 处置审计 | `disposition_audit` / `GET /api/audit` | 一条 `action='撤映'`, `outcome='成功'` |
| 4 | 互证卡 | `reconcile_cards` / `GET /api/reconcile-cards` | `formal=不在正式`, `conflict=在冲突`, `register=已撤映`, `verdict=一致` |
| 5 | 映射册 | `mapping_register` / `GET /api/register` | `state='已撤映'`，`new_key` 保留 |

五处任一不同态即判失败；`GET /api/reconcile-cards` 的 `inconsistent` 必须为 0。

## 并发口径

两路同时撤映同一实体：

- 锁以 `revoke_locks.entity_key`（即 `new_key`）为唯一键；同一实体（含多对一共享同一 `new_key` 的多个旧键）在并发生效窗口内视为同一实体。
- 占锁走**独立连接立即提交**，后到者一定能看见锁，不会因主事务未提交而漏判。
- 先到者执行撤映并成功；后到者占锁失败，返回 **409**，响应带 `contended: true`，`detail` 含“争用”。
- 后到者**不得**二次删除正式行、不得重复迁入冲突，只落一条 `action='撤映'`, `outcome='争用'` 的审计。
- 锁带 TTL（120s），持有者崩溃后过期可被接管；释放只删自己 owner 的锁，不误删他路。
- 无论撤映成败，`finally` 都释放本次锁，避免锁行残留把重映后的再撤误判为争用。
- 争用后五处仍须同态，互证卡 `verdict=一致`。

## 回滚口径

甲路径主事务内任一后置步骤失败（如迁冲突后写册/写卡失败）：

- 正式区删除、冲突区迁入、映射册状态、互证卡刷新**全部回滚**，实体仍在正式区、仍在册。
- 失败审计走独立连接独立提交，落 `action='撤映'`, `outcome='失败'`，保证账可追溯。
- 回滚后 `/api/orphans` 计数必须为 0。

## 冻结的顺序

1. 先见红：`test_revoke_leaves_no_orphan`、`test_concurrent_revoke_late_loser_marked_contended` 必须在改撤映写路径前失败。
2. 两条红测通过后才允许改撤映写路径。
3. 全绿后 `/api/conflicts` 可查、`/api/orphans` 只读可查。
4. 严禁跳过失败测、严禁无复现改角标。
